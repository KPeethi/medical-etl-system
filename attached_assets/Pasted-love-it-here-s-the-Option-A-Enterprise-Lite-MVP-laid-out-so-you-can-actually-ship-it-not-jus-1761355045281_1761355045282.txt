# A) What you’ll ship (scope)

**Goal:** Production-usable MVP that routes files into patient folders, lets humans fix the edge cases, and logs/audits everything cleanly.
**Not included yet:** FHIR/HL7, DICOM parsing, heavy OCR/ML. Those are phase-2.

## Core deliverables

1. **Router Service (Python)** — the engine: extract → transform (identity, modules, dedupe) → decisions → copy.
2. **Review Queue UI (Flask web app)** — fix *Unmapped / Bad DOB / Duplicates* with one click, then reprocess.
3. **Audit + DW tables (lite)** — append-only facts; provenance; SSIS-ready views.
4. **Security baseline** — PHI-safe logging, encryption hooks, least privilege.
5. **Ops niceties** — dry-run, canary, run summaries, configurable concurrency.

---

# B) Architecture (Hybrid)

```
Local Worker (per practice/clinic)
  - router_service
  - watches source shares / runs on schedule
  - never deletes source

Central Control (Flask UI + DB)
  - review queue (unmapped, dupes, bad DOB)
  - audit/events dashboard
  - API for job start/stop, reprocess
  - SSIS/SQL DW for reporting
```

# E) How you run it (MVP)

**Dry-run (default):**

```bat
python router_service\universal_router.py ^
  --src "\\server\practice\source" ^
  --dst "\\server\practice\Patients" ^
  --config "router_service\configs\practice_morse.yml" ^
  --log "\\server\practice\Log" ^
  --max-depth 12 --workers 24
```

**Real run:**

```bat
python router_service\universal_router.py ^
  --src "\\server\practice\source" ^
  --dst "\\server\practice\Patients" ^
  --config "router_service\configs\practice_morse.yml" ^
  --log "\\server\practice\Log" ^
```

# F) What the Review Queue gives you (Phase-1)

* **Unmapped:** list (filename, guessed name/DOB, reason). → Select patient from roster → Reprocess 1 click.
* **Bad DOB:** enter corrected DOB → Reprocess.
* **Duplicate inspector:** if “same name diff hash” → preview + keep/rename.
* **Reprocess controls:** per-file / per-patient / per-session.
* **Audit page:** who changed what, when (UTC), with before/after.

Minimal endpoints:

```
POST /api/reprocess/file     { file_id, reason, fix }
POST /api/reprocess/patient  { patient_id, session_id }
GET  /api/unmapped?session=…
GET  /api/audit?session=…
```

# H) Security baseline (day-1, no excuses)

* **PHI-safe logs:** never log raw OCR text or full names in DEBUG; redact with `security.redact()`.
* **Encryption hooks:** at-rest encryption for temp/cache folders (OS/volume level) and a toggle to AES-zip quarantine.
* **TLS:** enforce HTTPS for the central UI; self-signed acceptable in MVP; rotate later.
* **Least privilege:** router runs as `svc_router`, read-only to source, write to destination/log only.
* **UTC only:** all timestamps in UTC; UI shows local.

---

# I) Ops & SRE (just enough)

* **Run summary:** totals by action, top reasons, elapsed seconds.
* **Process heartbeat:** print every `--heartbeat-secs 10`.
* **Retry policy:** 1 retry for transient IO; error otherwise goes to `ERROR` bucket.
* **Backpressure:** `--workers` cap; optional `--max-mbps` later.
* **Disk guard:** stop if free space < 10% (configurable).

# L) Quick FAQ

* **OCR now or later?** Later. It’s slow and finicky; your filename/roster logic + manual review covers 90% fast.
* **Why Hybrid?** Files stay on-prem; you still get central visibility. Happy IT + happy operations.
* **How does reprocess work?** UI posts fix → router picks a “single-file job” with the original provenance → updates logs & DW.
